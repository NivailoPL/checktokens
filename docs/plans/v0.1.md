# CheckTokens v0.1 implementation plan

Accepted 2026-09-06. This document records decisions, not execution progress.

## Goal

Select one or more Finder files, right-click → Check Tokens, and see individual local text-token counts plus a total. The user chose the direct context-menu service on 2026-09-06; macOS can group it under Services. First release: macOS 15+, Apple Silicon and Intel. Public repository: NivailoPL/checktokens; MIT license; English UI and README.

## Product behavior

- One native scrollable result window per invocation, showing o200k_base, filenames, counts, errors, notes and sum. Copy results, close, progress and cancellation.
- Plain text/source files retain syntax and whitespace. Detect text beyond known extensions, support BOM-based Unicode and label heuristic legacy encoding detection.
- RTF uses striprtf. DOCX uses python-docx for body, nested tables and unique headers/footers; detected unsupported text boxes, revision marks, footnotes, endnotes and comments produce partial-read warnings.
- PDF uses pypdf in page order. Textless pages are reported without asserting they are scans. Fully textless, corrupt, inaccessible or password-protected documents receive an error; other files continue.
- Sum per-file counts, and mark partial totals whenever errors or warnings exist. A truly empty readable text file is zero; failed files have no numeric count.
- Skip directories without recursion. Limit files to 50 MiB, expanded DOCX content to 100 MiB and processing to 30 seconds per file. Do not truncate content silently.
- Operate offline after installation, including the first count. No API keys, telemetry, document modification, history or text logging.

## Architecture and interfaces

Python 3.12 portable extraction/counting/reporting core, locked dependencies, tiktoken encode_ordinary with bundled verified o200k_base resources. macOS-only AppKit/PyObjC UI and Automator Quick Action. Pass selected file paths as individual arguments, never executable shell code. Process each file in a cancellable, time-bounded worker outside the UI process.

CLI: checktokens [--json | --gui] -- FILE...; default text report. JSON includes per-file results and aggregate completeness. Exit 0 complete, 1 partial/failed, 2 invalid arguments. A direct app launch provides file selection.

## Implementation order

1. Scaffold repository, documentation, dependencies and meaningful counting tests.
2. Implement extraction, tokenizer, batch worker and CLI with error coverage.
3. Implement native UI, clipboard, cancellation and Finder workflow.
4. Package with PyInstaller onedir for each architecture. Include Python, dependencies, tokenizer resources, licenses and integrity manifest.
5. Per-user installer and uninstaller, idempotent update, rollback on install failure and preservation of unrelated files. Deliver ZIPs and SHA256SUMS through GitHub Releases separately from CI artifacts.

The user chose distribution without Developer ID/notarization. Retain PyInstaller's required ad hoc signatures and document Apple's first-run approval; do not disable Gatekeeper or strip quarantine automatically.

## Verification

- Fixed token examples, Unicode, special-token-like strings, BOMs, whitespace and empty files.
- Format fixtures with known extracted text, nested/merged DOCX tables, unsupported content warnings and PDF textless/password/corrupt cases.
- One/four/many file batches, partial errors, hostile-looking paths, size/time limits and cancellation.
- Fresh/update/uninstall and failed-update rollback, unrelated files/workflows preserved.
- Packaged CLI with network denied, empty tokenizer cache and no developer Python on PATH.
- Native Finder invocation and result window on the available Apple Silicon Mac; macOS 15 ARM and Intel build/runtime checks in CI. Record actual verification scope.

## Deferred

Windows integration reuses the portable core. OCR, alternate tokenizers, automatic updates, old Word/Pages formats and signed/notarized distribution are outside v0.1.
